## **Prompt: Enable/Disable Profile Editing Permissions (Super Admin Controlled) with Photo Management Improvements**

Implement a complete, production-ready profile editing permission system in the **User Management** section of the **Admin Dashboard**.

Before making any changes, perform a full analysis of the existing frontend, backend, API layer, authentication, authorization, database schema, Supabase RLS policies, profile module, user management module, and photo management workflow to ensure the implementation integrates correctly without breaking existing functionality.

---

# Objective

Allow the **Super Admin** to individually grant or revoke profile editing permissions for users from the **Active Users** list.

The implementation must be secure, scalable, fully responsive, and preserve all existing functionality.

---

# Functional Requirements

## 1. Add "Enable/Disable Editing" Option

Inside the **three-dot (⋮) More Options** menu for every **Active User**, add a new menu item:

* Enable Editing
* Disable Editing

Behavior:

* If editing is currently disabled, display **Enable Editing**.
* If editing is currently enabled, display **Disable Editing**.
* The label should automatically reflect the current state.

---

## 2. Permission Rules

Only the **Super Admin** can:

* Enable profile editing
* Disable profile editing

Regular Admins:

* Must never see this menu option.
* Must never be able to modify editing permissions through UI, API, or direct requests.

Students/Users:

* Cannot grant or revoke permissions.
* Cannot bypass restrictions.

The Super Admin must always retain unrestricted editing access.

---

## 3. Editable Fields

When editing is enabled for a user, that user should receive editing capability for only the following profile fields:

* Name
* Email Address
* Mobile Number

Each editable field must display:

* Pencil (✏️) edit icon
* Same editing UI
* Same validation
* Same save workflow

The behavior should match the current Super Admin editing experience.

---

## 4. Disabled State

When editing is disabled:

* Edit icons disappear.
* Fields become read-only.
* Existing profile layout remains unchanged.
* Users can still view their information.

No editing controls should remain visible.

---

## 5. Existing Profile Functionality

Do NOT modify:

* Password change
* Theme selection
* Notifications
* Profile image layout
* Account settings
* Download My Data
* Sign Out
* Appearance settings

Only control editability of the specified profile fields.

---

## 6. Photo Management Improvements

Review the entire profile photo workflow.

For users without a profile photo:

Display:

* Upload Photo

For users with an existing profile photo:

Display:

* View Photo
* Update Photo
* Delete Photo

Ensure:

* Correct permission validation.
* Existing upload functionality continues working.
* Image cache refreshes after update.
* Delete removes both database reference and storage object (if applicable).
* Proper success/error handling.
