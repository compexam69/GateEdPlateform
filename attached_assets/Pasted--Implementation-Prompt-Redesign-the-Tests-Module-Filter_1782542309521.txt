# Implementation Prompt: Redesign the Tests Module Filter Bar (Responsive, Functional & Production-Ready)

## Objective

Redesign the **top filter bar** in the **Tests** module while preserving all existing functionality. Replace the current status chips with a more compact and responsive filtering system that works seamlessly on both mobile and desktop devices.

The implementation must maintain the existing test data, business logic, APIs, filtering behavior, and performance while improving usability and screen utilization.

---

# Functional Requirements

## 1. Redesign the Top Filter Bar

Replace the current filter layout with the following responsive arrangement:

**Left**

* **Test Type** dropdown
* Default value: currently selected Test Type
* Preserve all existing Test Type options and behavior.

**Center**

* **Status** dropdown
* Default value: **All**
* Options:

  * All
  * Attempted
  * Passed
  * Failed
  * Total Attempts

**Right**

* Search icon only.

The filter bar should remain clean, modern, compact, and responsive.

---

## 2. Search Overlay

When the Search icon is tapped:

Open an **inline search popup/overlay inside the current page**.

Requirements:

* Do NOT expand the header.
* Do NOT push existing content downward.
* Do NOT resize the page.
* Do NOT overflow outside the viewport.
* Do NOT create horizontal scrolling.
* Do NOT shift surrounding UI elements.

Instead:

* Display a floating search field within the current page.
* Auto-focus the input.
* Allow searching by test name.
* Close via:

  * Close icon
  * Escape key (desktop)
  * Outside click/tap
* Preserve existing search functionality.

---

## 3. Status Dropdown Functionality

Move all existing chip functionality into the new Status dropdown.

Selecting an option should immediately filter the displayed tests without requiring additional actions.

Supported filters:

* All
* Attempted
* Passed
* Failed
* Total Attempts

The filtering logic must exactly match the previous chip behavior.

---

## 4. Remove Existing Status Chips

Completely remove the existing chips:

* Attempted
* Passed
* Failed
* Total Attempts

Requirements:

* Remove from UI.
* Remove unused styling.
* Remove unused state.
* Remove unused rendering logic.
* Remove obsolete event handlers.

Ensure no dead code remains after removal.

---

## 5. Preserve Existing Functionality

The redesign must NOT affect:

* Test loading
* Pagination
* Infinite scrolling (if applicable)
* Search logic
* Test Type filtering
* Attempt history
* Results
* Navigation
* API calls
* Performance
* Authentication
* Authorization

Only the UI presentation should change.
