Add Access Management for the "Notes" Module to My Existing Web Application

I already have a fully functional web application with an existing User Management system and role-based access control. Add access management for a new module named Notes.

Do NOT create a new project or modify unrelated existing functionality.

The Notes module must follow the same access-management pattern as the 75 Hard module.

ACCESS MANAGEMENT REQUIREMENTS

Super Admin

The Notes module must be enabled for every Super Admin by default.

Every Super Admin should automatically have access to the Notes module without requiring manual activation.

Super Admin can:

- Access the Notes module by default.
- Create, view, edit, and delete their own notes.
- Manage Notes access for other users.
- Enable Notes access for individual users.
- Disable Notes access for individual users.
- Enable Notes access for multiple users in bulk.
- Disable Notes access for multiple users in bulk.
- Manage Notes access from the existing User Management section.

---

OTHER USER ACCESS

The following users can access the Notes module only when a Super Admin explicitly enables access for them:

- Admin
- Student

Access must be granted individually from User Management.

Example:

- Admin A → Notes Enabled
- Admin B → Notes Disabled
- Student A → Notes Enabled
- Student B → Notes Disabled

Access must be managed independently for every user.

---

ACTIVE USERS ONLY

The Notes access-management feature must be available only for active users.

Super Admin should be able to enable Notes access only for users who are:

- Active
- Verified
- Existing users in the system

Inactive users must not be granted access to the Notes module.

If a user is later deactivated, their access to the Notes module must automatically become unavailable.

When the user becomes active again, handle their previous Notes access permission according to the existing application's permission logic.

---

USER MANAGEMENT INTEGRATION

Integrate Notes access directly into the existing User Management section.

Add a new access status/permission for every eligible active user:

Notes Access

Possible statuses:

- Enabled
- Disabled

The status should be visible for:

- Super Admin
- Admin
- Student

However:

- Super Admin: Enabled by default and cannot lose default access.
- Admin: Disabled by default until enabled by Super Admin.
- Student: Disabled by default until enabled by Super Admin.

ROUTE PROTECTION

Protect all Notes routes and pages using the existing authentication and permission system.

A user must not be able to access Notes by manually entering a URL if they do not have permission.

If a user does not have Notes access:

- Hide the Notes navigation item.
- Block direct URL access.
- Return an appropriate access-denied state.
- Do not load private Notes data.

The permission must be checked at both:

- Frontend/UI level
- Backend/API/database level

NOTES DATA PRIVACY

Users should only be able to access their own Notes data unless the existing application specifically provides a separate administrative viewing permission.

By default:

- Admin can access their own notes.
- Student can access their own notes.
- Super Admin can manage access permissions.
- Super Admin should not automatically expose private note content to other users unless an explicit administrative Notes permission is implemented.

Access to the Notes module and access to another user's private Notes content should be treated as separate permissions.

FINAL ACCESS LOGIC

Implement the following exact logic:

IF user.role === "Super Admin"
    Notes Access = TRUE by default

ELSE IF user.role === "Admin"
    Notes Access = TRUE only if Super Admin enables it
    Otherwise FALSE

ELSE IF user.role === "Student"
    Notes Access = TRUE only if Super Admin enables it
    Otherwise FALSE

IF user.status !== "Active"
    Notes Access = FALSE

IF user.isVerified !== TRUE
    User is not eligible for Notes access

ONLY Super Admin can:
    Enable Notes access
    Disable Notes access
    Perform bulk Notes access changes
