## **Prompt: Replace Dashboard Menu Button with Hamburger Navigation Drawer in the 75 Hard Module**

Implement a production-ready navigation improvement for the **75 Hard module**.

Before making any changes, perform a complete analysis of the existing frontend components, navigation structure, state management, animations, responsive layouts, icon system, routing, and all functionality currently associated with the Dashboard header menu. Ensure the new implementation integrates seamlessly without breaking any existing behavior.

---

# Objective

Replace the existing **small rounded-square menu button** on the right side of the **Dashboard header** with a **hamburger menu icon (☰)** that opens a smooth **right-side slide-out navigation drawer (off-canvas sidebar)** containing all existing menu items and functionality.

The implementation must be fully responsive, mobile-first, accessible, performant, and maintain the current dark theme and user experience.

---

# Functional Requirements

## 1. Replace the Current Menu Button

Replace only the current rounded-square menu button.

Requirements:

* Keep it in the exact same position.
* Maintain the same overall button size.
* Preserve the existing dark theme styling.
* Replace only the icon with a clean white hamburger icon (three horizontal lines).
* Vertically align the icon with the Dashboard title.
* Do not modify any other header elements.

---

## 2. Right-Side Navigation Drawer

When the user taps the hamburger icon:

Open a right-side off-canvas navigation drawer.

Requirements:

* Slide in smoothly from the right edge.
* Use hardware-accelerated animations.
* Maintain the existing dark theme.
* Display every menu item currently available in the rounded-square menu.
* Preserve the existing menu order.
* Preserve all existing functionality.
* Preserve existing navigation destinations.
* Preserve existing permissions and visibility rules.

No menu item should be removed, renamed, duplicated, or reordered unless already defined by the current implementation.

---

## 3. Drawer Closing Behavior

The navigation drawer must close when:

* User taps outside the drawer.
* User taps the hamburger icon again.
* User taps a close (✕) icon (if included).
* User selects a navigation item (after navigation completes).
* User presses the Android Back button (if applicable).

Ensure smooth closing animations.

---

## 4. Navigation Functionality

Verify that every existing menu action continues working exactly as before.

Ensure:

* Routing remains unchanged.
* Navigation state remains correct.
* Active page highlighting (if implemented) remains functional.
* Authentication and role-based permissions remain unchanged.

---

## 5. Mobile-First Responsive Design

Optimize the entire navigation experience for mobile devices.

Requirements:

* Responsive layout for all screen sizes.
* Proper spacing.
* Responsive typography.
* Responsive icon sizes.
* Responsive button sizes.
* Responsive drawer width.
* Responsive padding and margins.
* Responsive touch targets.

Use responsive units whenever appropriate:

* rem
* em
* %
* vw
* vh

or responsive utility classes (e.g., Tailwind responsive utilities).

Avoid unnecessary fixed pixel values.
